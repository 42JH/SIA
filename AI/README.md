# 멀티모달 AI 비서

## 자비스 모드 (메인 제품) — `python assistant.py`

커서를 건드리지 않는 시선+음성+제스처 비서. 사용법:

- **"자비스, ~"로 시작하는 명령이 한 번 통하면 90초 활성 세션** — 그동안은
  호출어 없이 바로 명령 (상단 배지에 남은 시간 표시, "그만"으로 즉시 종료)
- 명령 예: 화면 보며 "이거 저장해줘/요약해줘"(긴 답은 우상단 패널),
  "계산기 켜줘", "○○ 검색해줘", "○○ 파일 찾아줘", "창 최대화/최소화",
  "스크롤 내려", "10초 뒤로"·"음소거"(영상), "창 닫아"(음성 재확인 후 실행)
- **창 조작·미디어 제어는 "말하던 순간의 창"이 대상** — 말한 뒤 다른 데를
  클릭해도 의도한 창이 조작된다 (발화 시점 HWND 고정)
- 제스처 커맨드(gestures.json): 기본 컨텍스트에선 앱 실행, **유튜브 시청 중엔
  같은 제스처가 재생/음소거/건너뛰기로 자동 전환** (기획서 4번)
- 안전장치: 비음성(음악·기계음) 기각, 호출어 없는 발화로는 세션이 절대 열리지
  않음(코드 게이트), 파괴적 동작은 음성 재확인, `--no-actions`로 전체 리허설

Gemini 키: `gemini_api_key.txt` 또는 환경변수. 모델·호출어는 `GEMINI_MODEL`,
`WAKE_WORD` 환경변수로 변경.

**커스텀 제스처** (기획서 6번): `python gesture_studio.py`로 자기만의 손모양을
등록 (샘플 30장 수집 → 내장·기존 제스처와 혼동도 검사 → 앱 연결).
`--test`로 라이브 확인, `--list`/`--remove 이름`으로 관리.

**DOM 브리지** (BE 크롬 확장 연동 지점): 에이전트가 `127.0.0.1:8765`에서
브라우저 컨텍스트를 수신 — 계약은 `DOM_브리지_계약.md`. 확장이 없으면
스크린샷 기반으로 자동 폴백 (기능 손실 없음, 품질만 차이).

# (부록) 손 커서 데모 v0 — `python main.py`

웹캠 하나로 **시선 + 손 제스처**로 PC를 조작하는 데모.
Vision Pro 인터랙션 모델: **보면 하이라이트, 핀치로 확정.**

핵심 설계 — 시선은 커서를 움직이지 않는다. 백그라운드 링버퍼에서 항상
추적만 하다가, 트리거(핀치) 순간에 **직전 fixation**으로 커서를 워프시킨다.
(Midas touch·떨림 문제를 구조적으로 회피. 사람 눈은 행동 전에 대상을 떠나므로
트리거 시점이 아니라 250ms 전 fixation을 조회한다.)

## 설치 & 실행

```
python -m venv .venv
.venv\Scripts\pip install -r requirements.txt
.venv\Scripts\python test_core.py         # 카메라 없이 로직 검증
.venv\Scripts\python main.py --check      # 카메라·모델·fps 점검
.venv\Scripts\python calibrate.py         # 9점 시선 캘리브레이션 (최초 1회)
.venv\Scripts\python main.py --gaze-test  # 시선만 따로 확인 (점이 눈을 따라오는지)
.venv\Scripts\python main.py              # 데모 시작
```

모델 파일(`models/*.task`)은 포함돼 있음. 없으면 Google 공식 저장소에서:
- https://storage.googleapis.com/mediapipe-models/face_landmarker/face_landmarker/float16/latest/face_landmarker.task
- https://storage.googleapis.com/mediapipe-models/gesture_recognizer/gesture_recognizer/float16/latest/gesture_recognizer.task

## 딥 시선 모델 (선택 — 정확도 업그레이드)

torch(CUDA) + `models/eth-xgaze_resnet18.pth`(ETH-XGaze 사전학습, 45MB)가 있으면
CNN 시선 각도 2개가 특징에 추가돼 14차원 회귀가 된다 (없으면 기하 12차원 자동 폴백).
가중치: https://github.com/hysts/pytorch_mpiigaze_demo/releases/download/v0.2.2/eth-xgaze_resnet18.pth
(ETH-XGaze 데이터셋 라이선스는 연구 목적 — 학술/데모용으로만 사용)

**딥 모델을 켜거나 끄면 특징 차원이 바뀌므로 재캘리브레이션 필수** —
main.py가 차원 불일치를 감지하면 시선을 끄고 안내를 출력한다.

## 조작법

| 동작 | 기능 |
|---|---|
| **손 이동** | **커서 이동 (에어 트랙패드)** — 커서 주도권은 항상 손 |
| 손바닥 펴고 0.6초 | Active ↔ Passive 토글 (클러치). `--auto-active`면 손만 보여도 Active |
| 핀치 짧게 (<0.35초) | 현재 커서 위치 클릭. 빠르게 2번 = 더블클릭 |
| 핀치 0.35초 이상 홀드 | 드래그 — 창 이동, 텍스트 선택 |
| 먼 곳 보고 핀치 | 응시점이 커서에서 300px 이상 멀면 커서가 그 근처로 점프(요소 스냅) 후 위 규칙 그대로 |
| V사인 + 손 상하 | 응시 지점 스크롤 |
| 따봉 | 응시 지점 우클릭 |
| 화면 상단 배지 | 현재 상태 상시 표시 (PASSIVE/ACTIVE/PINCH/DRAG) |
| ESC (미리보기 창) | 종료 |
| 마우스를 좌상단 모서리로 | 즉시 비상 정지 (pyautogui failsafe) |

설계 원칙: **정확한 신호(손 랜드마크, 픽셀 단위)가 커서를 조종하고, 부정확한
신호(웹캠 시선, ~200px)는 장거리 점프 생략이라는 보조 역할만 한다.**
워프 민감도는 main.py 상단 `WARP_MIN_DIST`로 조절 (크게 = 시선 개입 축소).

파이프라인은 3스레드(카메라 캡처 / 시선 / 손+인터랙션)로 분리돼 서로를
기다리지 않는다 — 손 커서는 ~30fps, 시선은 ~20fps로 각자 돈다.
드래그 손떨림 필터는 One Euro (정지 시 부드럽고 이동 시 지연 없음).

Passive 상태에선 아무것도 조작되지 않는다. Active여도 시선만으로는
아무 일도 일어나지 않는다(링 표시만). 손이 15초 안 보이면 자동 Passive.

안전 규칙 (구현돼 있음):
- 시선이 불확실하면(두 지점을 오가는 중, 추적 끊김, 1초 이상 오래된 데이터)
  워프하지 않는다 — 핀치는 현재 커서 위치에서 동작, 우클릭은 무시.
- 제스처 분류는 3프레임 연속일 때만 인정 (한 프레임 오분류 방지).
- 클러치·따봉은 손을 내렸다 다시 들어야 재발동.
- 해상도가 캘리브레이션 당시와 다르면 시선 자동 비활성 + 경고.
- 어떤 경로로 종료돼도(ESC·failsafe·예외) 마우스 버튼을 잡은 채 남지 않는다.

`--no-mouse`: 실제 마우스 제어 없이 콘솔 로그만 — 첫 리허설용 추천.

## 파일 구조

- `gaze.py` — 홍채+머리자세 특징, 2차 ridge 캘리브레이션, 링버퍼+fixation
- `hands.py` — GestureRecognizer 래퍼, 핀치 FSM(히스테리시스), 클러치 토글
- `overlay.py` — 응시 링 오버레이 (click-through 투명 창)
- `calibrate.py` — 9점 캘리브레이션 UI (`--grid 4x3` 가능)
- `main.py` — 메인 루프·상태머신·마우스 제어 (튜닝 노브는 파일 상단)

## 팁 / 알려진 한계

- **손 인식이 안 될 때**: 손을 카메라에서 50~80cm 안, 가슴~어깨 높이로 들고
  손바닥이 카메라를 향하게. 미리보기 창에 초록 점(스켈레톤)이 찍히는지 확인 —
  안 찍히면 인식 자체가 안 되는 것(거리/조명 문제), 찍히는데 제스처가 "None"이면
  분류 문제(손 각도). `a` 키로 손 없이 Active를 수동 토글할 수 있다.
- **시선이 되는지 궁금할 때**: `python main.py --gaze-test` — 전체화면에서
  원이 눈을 따라오면 정상. 원이 화면 구석에 붙거나 안 움직이면 재캘리브레이션.
- 웹캠은 **모니터 상단 중앙**, 얼굴 조명 균일하게. 안경 반사가 최대 적.
- 시선 정확도는 영역 수준(수 cm). 버튼 하나 집기는 핀치 홀드 후 손으로 미세조정.
- 자세가 크게 바뀌면 재캘리브레이션 (`python calibrate.py`).
- 캘리브레이션 잔차 RMS가 화면 셀 반지름보다 크게 나오면 환경부터 고칠 것.

## 클릭 기반 상시 재보정 (기본 켜짐, `--no-recal`로 끄기)

실물 마우스로 클릭하는 순간 그 좌표를 보고 있을 확률은 거의 100% —
클릭할 때마다 (시선 특징 → 클릭 좌표) 정답 쌍이 공짜로 쌓인다.
5개 모일 때마다 기본 캘리브레이션과 합산 재학습하고 디스크에 저장하므로
**쓰면 쓸수록, 특히 자주 클릭하는 영역에서 정확해진다.**

- 데모가 만든 합성 클릭은 제외 (자기 예측을 정답으로 배우는 피드백 루프 방지)
- 클릭 150ms 전 특징을 사용 (눈은 클릭 전에 이미 대상 위에 있음)
- 예측과 500px 이상 어긋난 클릭은 무시 — 딴 데 보면서 한 클릭은 오답 라벨
- 전역 클릭 리스너는 좌표만 쓰며 전부 로컬 저장 (`models/clicks.npz`)
- calibrate.py를 다시 돌리면 이전 캘리브레이션은 `calib_backup.npz`로 백업되고
  클릭 샘플은 초기화된다 (옛 자세 기준 샘플이 새 캘리브레이션을 오염시키므로)
