# 한 손 동적 제스처 2D/3D 비교 평가

## 적용 내용

기존 한 손 동적 제스처는 2D 손 좌표·궤적·회전·손 모양을 비교했다. 이번 브랜치에서는 새 촬영에서 모든 프레임에 유효한 MediaPipe world landmark가 있으면 3D 손 모양 궤적도 함께 저장한다.

실행·등록 비교는 기존 2D 점수와 world 3D 점수 중 더 큰 값을 사용한다. 2D는 화면 안 이동 방향과 이동 궤적을 보존하고, 3D는 카메라 시점에 덜 민감한 깊이·손가락 형태 차이를 보완한다. 한 손 좌우 반전 규칙은 2D 궤적 비교에 그대로 적용한다. world 데이터가 없거나 일부 프레임만 유효하면 기존 2D로 안전하게 폴백한다.

3D 데이터가 없던 기존 동적 NPZ는 자동 변환하지 않는다. 새로 등록하거나 동작 재촬영해 world_valid=true가 저장된 템플릿부터 2D+3D 경로를 사용한다.

## 정량 비교

동일한 화면 궤적을 두고 깊이 방향에서 한 손가락이 달라지는 합성 케이스를 1,000회 반복했다. 임계값은 기존 실행 기준 0.22다. 점수는 확률이 아니라 거리이며 낮을수록 가깝다.

| 케이스 | 2D 점수 | 2D+3D 점수 | 2D 판정 | 2D+3D 판정 |
|---|---:|---:|---|---|
| 동일 동작 | 0.0000 | 0.0000 | 매칭 | 매칭 |
| 화면상 동일·깊이 변화 | 0.0000 | 0.1867 | 매칭 | 매칭(거리 증가) |

깊이 변화가 더 커져 3D 점수가 0.22를 넘으면 3D 경로는 같은 화면 궤적을 다른 동작으로 거부할 수 있다. 현재 샘플에서는 깊이 변화가 임계값 아래였으므로, 이 결과만으로 인식률 상승을 주장하지 않는다.

| 측정 | 결과 |
|---|---:|
| 비교 실행 시간 중앙값 | 1.923ms |
| 비교 실행 시간 95백분위 | 4.314ms |
| 동일 좌표 2D+3D 매칭 | 1,000/1,000 |
| 3D 동작 전용 테스트 | 3/3 통과 |
| 전체 AI 회귀 테스트 | 212/212 통과, 28.385초 |

원자료는 [dynamic-2d-vs-3d-evaluation.json](dynamic-2d-vs-3d-evaluation.json)이다. 비교 스크립트는 `python evaluate_dynamic_2d_vs_3d.py`로 재현한다.

## 2D와 3D 중 어느 쪽이 나은가

동적 제스처의 이동 방향·화면 궤적은 2D가 필요하므로 3D만 쓰는 방식은 적절하지 않다. 반대로 손가락 깊이·손등 방향처럼 화면 투영만으로 겹치는 동작은 2D만으로 구분하기 어렵다. 현재 구현에서는 **2D를 기본으로 유지하고 유효한 3D가 있을 때 두 점수의 최댓값을 사용하는 혼합 방식이 더 안전하다.** 기존 동작의 인식 범위를 갑자기 바꾸지 않으면서, 깊이에서 크게 다른 동작의 중복 등록을 차단할 수 있다.

단점은 world landmark가 카메라·손 가림에 민감하고, 3D가 없는 기존 등록은 개선되지 않는다는 점이다. 실제 카메라에서 좌우 손과 손등 방향을 각각 3회 이상 재촬영해 다음을 별도로 측정해야 한다.

- 동일 동작 중복 거부율
- 정상적으로 다른 동작을 잘못 거부하는 오거부율
- 의도한 실행 인식률
- 다른 제스처 오발동률
- 등록·실행 거리 계산 지연의 중앙값과 95백분위

이번 평가는 합성 깊이 변형과 저장 좌표를 사용한 코드 검증이다. 라이브 카메라 인식률 80% 또는 손등 방향의 100% 차단을 의미하지 않는다.
