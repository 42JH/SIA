- Jira: S15P21D106-286(본작업) · -291(후속, MR !75) · -294(라이브 피드백 반영)

## 2. 원인 분석 (세 가지가 겹쳤다)

### 2-1. STT 디코딩 설정 — base·cpu·int8·beam1, 어휘 힌트 없음
- 같은 클립에서 모델·디코딩만 small·cuda·fp16·beam5 + `initial_prompt`로 바꾸자 6→22/27. 모델 크기보다 **beam5 + 어휘 프롬프트**가 결정적이었다(small·cuda·beam1·프롬프트 없음은 6/27로 base와 같음).
- 프롬프트는 사전 표(`APPS_KO`, `MEDIA_KO`)에서 생성해(`DEFAULT_PROMPT`) 사전과 항상 같이 움직인다.
- GPU를 안 쓰고 있던 이유: ctranslate2가 `cublas64_12.dll`을 못 찾아 CUDA 로드가 실패 → CPU가 기본. `import torch`를 먼저 하면 torch/lib의 cuBLAS·cuDNN DLL을 공유해 별도 CUDA 설치 없이 동작.

### 2-2. 게이트 이중검사 — 통과한 발화를 라우터가 다시 막음
- `brain._try_router`가 `route(text, session_active)`로 호출 → 라우터가 **전사 텍스트에서** 호출어 "시아야"를 다시 찾았다.
- 그 발화는 이미 -211 게이트(openwakeword + 호출어 템플릿 + 화자 유사도)를 **오디오 기준으로** 통과한 것. 전사에서 "시아야"가 `자야`, `쇼야`, `샤이`로 뭉개지면 라우터가 세션 밖 발화로 오판해 승격.
- 수정: `route(text, True)` — 게이트 판정은 오디오 단계 한 곳에서만. 평가기도 같은 기준으로 채점.

### 2-3. 사전·규칙 결함 — 전사가 맞아도 안 잡힘
- `틀어`가 playpause에 먼저 걸려 "다음곡 틀어줘" → playpause **오답** → playpause를 맨 뒤로, `OPEN_VERBS`에 `틀어`.
- 볼륨은 붙어 있어야 잡힘("볼륨 좀 올려줘" 미스) → 명사(볼륨/소리) + 동사(올려/내려…) 쌍 매칭.
- 종료 인사(수고하셨, 다음에 만나)가 MEDIA 뒤에 있어 media로 먹힘 → END 우선.
- "시아야 메모장 해줄래?" — `해`를 열기 동사로 넣으면 "메모장 저장해줘"도 열려서, 앱 이름 뒤에 **군말만** 남으면 열기(`APP_ONLY_REQ` + 잔여 계산).
- STT가 "야"를 자주 떨어뜨림(`시아. 메모장 해줄래?`) → `WAKE_VARIANTS`에 `시아`.

## 5. 라이브 검증 (9/16 팀원 로그)

```
STT 모델 로드 (small, cuda/float16, beam 5, 1.4s)
[1단 0.33s] '소리 80까지 높여줘.' → media
[지연] 대기 -1.69 | 게이트 0.35 | STT 0.33 | DOM None | LLM None(None) | 실행 0.04 | 발화끝→완료 0.69s
```

- GPU 경로가 라이브에서 확인됐고, 사전 명령은 게이트 0.35 + STT 0.33 + 실행 0.04로 끝났다.
- 여기서 나온 문제 네 건과 대응(-294):
  1. **"크롬 켜줘" → `크롬 펴줘`** 전사로 승격 → 자모 유사도 규칙(§4).
  2. **"소리 80까지"가 +2만 올라감** — volup 한 단계 키 입력으로 처리됐기 때문. 숫자(80·팔십·백)+조사 파싱 → `volset+level` → BE MCP `volume.set`.
  3. **첫 발화가 모델 로드 1.4~5초를 떠안음** → 시작 직후 `Router.warm()` 백그라운드 예열(로드 잠금). 예열 뒤 첫 전사 0.19s.
  4. **`대기 -1.69`** — 발화 종료 시각을 `t_utter + 오디오 길이`로 잡아 프리롤 2초만큼 늦었다. 세그먼트 도착 시각 - VAD 종료 침묵 0.55s로 교체.
- 라이브 전제조건: `models/wake.npz`(호출어 등록)가 없으면 -211 게이트가 발화를 전부 버려 STT 자체가 돌지 않는다. 기본 마이크가 가상 장치(Voicemod 등)면 물리 마이크를 선택한다. venv torch는 cu128 빌드여야 GPU를 탄다(CPU 빌드면 자동 CPU 폴백 2.4s).
